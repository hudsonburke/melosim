# Bevy-Native Editor Plan — Layered (Part ↔ Model)

> **For Hermes:** agency via subagent-driven-development; verify each phase with a real
> build + window run before moving on.

**Goal:** A Bevy-native, **layered** editor for biomechanical models and exoskeletons:

- **Layer 1 — Part / Entity editor:** author a reusable component — import a mesh, add
  **Sites** (cable-routing / landmark points) and **Frames** (attachment frames), save it as a part.
- **Layer 2 — Model editor:** assemble a full model — instantiate parts, **attach** a part to a
  body via a Frame, **joint it** to another body (so the exoskeleton becomes a real articulating
  segment), route cables through its Sites, and export to MJCF/OSIM.

**Decision (2026-08-18):** Stay **native Bevy** for every surface. No jackdaw, no egui.

## Disposition of the existing editor (scrap & rebuild)

The current `src/editor/` (hierarchy, inspector, toolbar, viewport) is a **throwaway prototype** —
Hudson did not like how it turned out, and we are **not** beholden to it. Build the new layered editor
fresh. Carry forward only what is genuinely good:

**Keep (already solid, reused as-is):**
- `src/model/` — the Bevy component data model (Body, Frame, Site, Joint, Coordinate/Twist/CoordinateState, Muscle, PathEntities) and nalgebra f64 math.
- `sync_kinematics` — the PoE screw-theory FK that maps coordinate state → f32 render transforms.
- `src/render/` gizmo systems (muscle paths, joint axes) and `bevy_picking` click-to-select + selection highlight.
- The Bevy baseline (Feathers theme, free camera, infinite grid).

**Scrap — do not salvage:**
- The old inspector's `gather-then-despawn-and-rebuild` pattern and read-only value rows; replace with ECS-driven, reactivity-based per-field editors (Editor core below).
- The old hierarchy/toolbar panels as-is; re-implement against the layered Part ↔ Model model.
- Any layout/shortcut choices that only made sense for the old design.

The new editor is a **fresh implementation** of the sections below. The old panels remain only until
replaced (kept compiling so the tree stays green during the transition).

## Why layered & native

A "part" **is a Bevy scene (template)** — a serialized sub-graph of components (mesh + Sites +
Frames) that you later **instantiate** into the model world. That is Bevy's prefab pattern, and it
drops straight onto the existing model components:

| Concept | Existing component |
|---|---|
| Part body / mesh holder | `Body` + `Mesh3d`/`MeshMaterial3d` (+ `InertialProperties`) |
| Cable-routing / landmark points | `Site` (child entity + `Transform`) |
| Attachment frames | `Frame` (child entity + `Transform`) |
| Joint = one body to another | `Joint` + `Coordinate` + `Twist` (`JointCoordinates`/`CoordinateOf` rel.) |
| Cable path through Sites | `PathEntities` (ordered list) |
| Pose / FK | `CoordinateState` → `sync_kinematics` (PoE screw FK) |

The **two layers share one editor core** and differ only in document type (a Part vs a Model) and
active toolset.

```
Editor
├── Editor core (shared)          ← viewport, camera, grid, picking, hierarchy,
│                                   inspector, transform gizmo, undo/redo
├── Layer 1: Part editor          ← mesh import, Site/Frame placement, save part (BSN scene)
└── Layer 2: Model editor         ← part instantiate, attach (Frame), joint tool,
                                    cable routing, export MJCF/OSIM
```

### Most-Bevy-native principles (apply everywhere)

1. **UI is a view over ECS state** — no parallel data model, **no despawn/rebuild on every change**.
   Use change detection + observers so only nodes whose component changed are touched.
2. **Model components are the single source of truth.** Every edit flows through
   `Commands`/component mutation; `sync_kinematics` reacts. Funnel UI edits into the same path.
3. **Native toolkit:** `bevy::feathers` (UI), `bevy_picking`, `bevy_gizmos`, BSN
   (`bevy_world_serialization`).
4. **Reusable widgets are Bevy components** with their own systems.
5. **Undo/redo is an observer/command pattern over the ECS**.
6. **Parts are scenes; models instantiate parts.**

## Editor core (shared, built first)

- Layout root (Feathers Node): top Toolbar, left Hierarchy, right Inspector, center Viewport.
- **View systems**: read model components → update only the affected UI nodes (change detection +
  observers). Kill the gather-then-despawn/rebuild pattern in the current inspector.
- **Widget library** (components + systems): `Slider<float>`, `DragValue`, `Toggle`, `TextField`,
  `Dropdown`, `Section` (collapse), `Row`/`Grid`. Each binds to `(Entity, field)` and emits a change
  → `Commands`.
- **Picking** (already present): click-to-select, walk `ChildOf` to the owning model entity.
- **Transform gizmo**: translate (axis-arrows + plane handles) & rotate (arcs) via `bevy_gizmos` +
  picking; drags write model `Transform` with live FK.
- **Undo/redo**: observer/command stack over entities, snapshot affected components, Ctrl+Z /
  Ctrl+Shift+Z.
- **Explicit per-component editors**, not a generic Reflect inspector (domain semantics: limits,
  clamped, units matter; and `Twist` fields are `#[reflect(ignore)]` nalgebra).

## Layer 1 — Part / Entity editor

Document = a single **Part**: a `Body` (or bare entity) with a mesh and a set of Sites/Frames.

1. **Mesh import** — GLTF/STL dialog → `Mesh3d`/`MeshMaterial3d` under the part's Body.
2. **Add Site** tool — place `Site` (child + `Transform`), name it. List/manage in a side panel.
3. **Add Frame** tool — place `Frame` (child + `Transform`), name it; used later for attachment.
4. **Manipulate** — select a Site/Frame/Body and move/rotate with the gizmo; edit numeric fields
   in the inspector.
5. **Save part** — serialize the part sub-graph (Body + mesh + Sites + Frames) to a **BSN part
   asset** (`assets/parts/<name>.bsn`), ready to instantiate.
6. **Load part** — open a saved part back into the part editor for iteration.

## Layer 2 — Model editor

Document = a full **Model** (skeleton or assembled exoskeleton).

1. **Load skeleton** — via importer (MJCF `mujoco-rs` / OSIM `opensim` feature) or a BSN scene
   (e.g. the myoarm sketch).
2. **Instantiate part** — spawn a saved part scene into the model world as children of a chosen body.
3. **Attach tool** — pick a part `Frame` + a target `Body` → parent the part under the body's local
   frame (or a station/landmark-defined frame later). This is "bring exo onto the skeleton".
4. **Joint tool** — pick two bodies/parts → spawn `Joint` + `Coordinate`(s) + `Twist`(s) connecting
   them (`JointCoordinates`/`CoordinateOf`). `sync_kinematics` FK picks it up; gizmo shows the new DOF
   axis; inspector edits range/clamped/limits. This is "joint it to another body".
5. **Route tool** — build/order `PathEntities` through Sites for a muscle/cable; live redraw via
   `draw_muscle_paths` gizmo.
6. **Export** — assembled model → MJCF/OSIM; re-import diff verifies roundtrip.

## Phases

### Phase 0 — Build baseline cleanly (½–1 hr)
`nix develop --command cargo check` clean; `cargo run` / `cargo run --example myoarm_sketch`
opens without panics. Fix the "Bad version of editor" compile issues. Define a repeatable verify step.

### Phase 1 — Editor core: view/reactivity rework (2–3 hrs)
Rework the inspector from gather-then-rebuild to **ECS-driven, per-field child nodes** that update
only on change. This is the reactor that both layers run on.

### Phase 2 — Editor core: Feathers widget library (2–3 hrs)
`Slider`, `DragValue`, `Toggle`, `TextField`, `Dropdown`, `Section`, `Row/Grid` as Bevy components +
systems (themed via `UiTheme`, target-aware, emit edits → `Commands`).

### Phase 3 — Editor core: per-component inspector editors (2–3 hrs)
Editors for Body, InertialProperties, Site, Frame, CoordinateProperties, Twist, Hill-type params.
Live FK on edit.

### Phase 4 — Editor core: transform gizmo + undo/redo (2–3 hrs)
Axis/plane + arc handles (custom slim gizmo or `bevy_mod_gizmo`); drag → model `Transform` → FK.
Observers/command stack undo/redo.

### Phase 5 — Layer 1: Part editor (2–3 hrs)
Mesh import; Add-Site / Add-Frame tools; part side panel (list, rename, reposition, delete);
**save/load part as a BSN scene asset**.

### Phase 6 — Layer 2: Part instantiation + attach + joint tools (3–4 hrs)
Instantiate saved parts; Attach tool (Frame→Body); **Joint tool** (spawn Joint/Coodinates/Twist,
FK reacts). Load myoarm + attach the lower-arm exo; verify articulation.

### Phase 7 — Cable routing + export roundtrip (2–3 hrs)
Route tool (`PathEntities` through Sites, live gizmo); re-enable importer; export MJCF/OSIM,
re-import diff on unedited models.

### Phase 8 — Later (optional)
Station/landmark-defined attachment frames (StationDefinedFrame), wrapping surfaces,
muscle param graphs, body labels, scene-tree drag-reparent, exo-arm preset library.
